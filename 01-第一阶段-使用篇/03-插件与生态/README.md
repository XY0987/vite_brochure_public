# 第一阶段 · 使用篇 / 03 插件与生态

> 本章对应《Vite：从使用到精通》第一阶段第 3 项「插件与生态」。
> 事实基线：2026 年中，Vite 8.x（Rolldown 1.0 已于 2026.05 稳定，Vite 8 默认唯一打包器，Oxc 接管转译/压缩）。

本章目标：把你从「会用别人写的插件」带到「看得懂插件、能自己写插件、会组合一堆插件而不踩顺序坑」。具体回答三个问题——**插件到底是什么、能挂哪些钩子（01）；为什么 Vite 插件长得像 Rollup 插件、它俩什么关系（02）；真实项目里那一长串官方/社区插件怎么选、怎么排顺序（03）**。

## 这一章和前两章的关系

[01 核心使用](../01-核心使用/README.md) 讲了 dev 请求链路 `resolveId → load → transform` 和 HMR 通道；[02 框架集成](../02-框架集成与测试/README.md) 已经让你见识过「框架插件 = 在 `transform` 里编译 + 注入 HMR」。本章把这层窗户纸彻底捅破：

- 一句话主线：**Vite 的几乎所有能力（包括框架支持、CSS、别名、HMR）都是用插件 + 钩子拼出来的；插件系统是一套兼容 Rollup 的钩子模型。** 你在 02 章手写过的「迷你框架插件」，正是本章 01 节系统讲的插件的一个特例。
- 所以本章会反复引用 01 章的请求链路图和 02 章的 `transform` 例子，建议先读完那两章。

## 阅读建议

01 是地基，必读——它把「插件能挂哪些钩子、各自时机」一次讲全。02 解释「为什么是这套钩子」，想搞清 dev/build 行为差异、或将来要读源码（第二阶段）的读者重点看。03 是最贴近日常的实战，讲清真实项目里插件怎么挑、怎么排序，所有人都用得到。顺序读最佳，急用可直接跳 03。
