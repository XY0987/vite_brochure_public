# 第一阶段 · 使用篇 / 04 多环境与工程化场景

> 本章对应《Vite：从使用到精通》第一阶段第 4 项「多环境与工程化场景」。
> 事实基线：2026 年中，Vite 8.x（Rolldown 1.0 已于 2026.05 稳定，Vite 8 默认唯一打包器，Oxc 接管转译/压缩）。

本章目标：把前三章学到的「单应用怎么用 Vite」推进到**真实团队工程**的复杂场景——同一份代码要产出多个运行目标（浏览器/Node/边缘）、项目是 monorepo 一堆内部包、上了 SSR、最后还要稳定部署上线。这些是 demo 教程通常略过、却最能区分「会配 Vite」和「能扛住生产」的部分。本章逐个攻克：**多环境多运行时（01）、monorepo 依赖治理（02）、SSR 工程坑位（03）、部署与 CI 缓存（04）**。

## 这一章和前几章的关系

前三章（[核心使用](../01-核心使用/README.md)、[框架集成](../02-框架集成与测试/README.md)、[插件与生态](../03-插件与生态/README.md)）讲的是「在一个应用里把 Vite 用好」。本章换一个视角：**当应用进入真实团队工程——多目标、多包、SSR、要上线——会冒出哪些新问题，Vite 怎么应对。**

- 一句话主线：本章的四个主题都是「单应用经验失效」的地方——单应用没有「多环境」、没有跨包软链、没有「两个世界各跑一遍」、没有部署路径问题。这里把这些工程现实逐个补上。
- 强关联前文：03 SSR 大量复用 [01 章的最小 SSR](../01-核心使用/06-SSR库模式多页应用.md) 与 `import.meta.env`；02 monorepo 的 `noExternal` 又和 03 SSR 外部化相互呼应；04 的类型检查卡点延续 [01 章 TypeScript 处理](../01-核心使用/07-TypeScript处理.md) 的「Vite 只转译不检查」。
