# 第三阶段 · 哲学篇（道与术）

> 本阶段对应《Vite：从使用到精通》第三阶段「哲学层面（道与术）」，共 7 节。
> 事实基线：2026 年中，Vite 8.x（Rolldown 1.0 已于 2026.05 稳定，Oxc 接管转译/压缩）。

前两个阶段我们分别回答了「**怎么用**」（第一阶段）和「**怎么实现**」（第二阶段）。第三阶段回答最后一个、也是最难的问题：**「它为什么这么设计」**。

这一阶段的目标不是再教你一个 API 或一处源码，而是**忘掉具体实现，把前两阶段沉淀的经验升华为可迁移的设计思想**——下次你面对一个全新的框架、工具，甚至要亲手设计一个系统时，能用同一套判断方式快速看懂它的取舍、预判它的演进、评估它的代价。

## 这一阶段为什么不空谈

「设计哲学」最容易写成正确的废话——"要平衡""要权衡""要演进"谁都会说。本阶段坚持一条铁律：

1. **每节强制绑定前两阶段至少一个具体案例**，先复盘真实发生过的技术决策，再抽象；
2. **先复盘、再抽象**：从「Vite 当时面对什么约束、做了什么选择、付了什么代价」出发，提炼出一个可复用的判断框架；
3. **每节给一个迁移练习**：用同一套判断方式去分析另一个工具/框架（webpack、Turbopack、Next.js、Bun、SWC……），把「读懂 Vite」变成「读懂一类系统」。

换句话说：**道从术中来**。每一条「哲学」背后，都站着第二阶段一个可以打断点的真实链路、第一阶段一个真实踩过的坑。

## 阅读建议

- **建议先读完前两阶段**：本阶段几乎每段论述都会指回第一/第二阶段的具体章节。如果你跳读到这里，至少先扫一遍第二阶段的 [专题01 双引擎的历史与代价](../02-第二阶段-源码篇/02-底层引擎与生态对比/专题01-双引擎的历史与代价.md) 与 [主线07 插件容器](../02-第二阶段-源码篇/01-Vite实现原理/07-插件容器PluginContainer.md)、[主线10 Environment API](../02-第二阶段-源码篇/01-Vite实现原理/10-多环境模型EnvironmentAPI实现.md)，否则案例会缺少落点。
- **顺序读最佳**：01（复杂度是一切权衡的总纲）→ 02（抽象这把双刃剑）→ 03（决策的时机维度）→ 04（演进的兼容维度）→ 05（性能换可维护性的代价）→ 06（AI 时代如何建立确定性）→ 07（把全部收束成方法论）。
- **重在迁移**：每节末尾的「迁移练习」才是这一阶段的真正产出。读完 Vite 的案例只是输入，能拿同一套框架去拆解下一个工具，才说明这一阶段对你生效了。
